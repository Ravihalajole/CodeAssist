# AGENTS.md

CodeAssist — Android app (Kotlin) that runs an LLM "agent" against a user-selected workspace: it parses `:::CODE_ASSIST:::` clipboard envelopes, applies file mutations via JGit, and (through the accessibility service) can observe and drive other apps on the device.

## Build & run

- Single-module Gradle project: `:app` (Kotlin DSL, version catalog in `gradle/libs.versions.toml`). Wrapper = Gradle 9.0.0, AGP 8.13.0, Kotlin 2.1.0.
- `compileSdk=36`, `minSdk=23`, `targetSdk=34`, `versionCode=2`/`versionName="1.1"`. Java/Kotlin target = 17.
- View binding on; no Compose, no kapt. No `test`/`androidTest` sources exist — don't try to run a test suite.
- `local.properties` is machine-specific and not tracked (`.gitignore`); there is none checked out. Builds need a real SDK path — set `local.properties` (`sdk.dir=...`) or `ANDROID_HOME`. CI (`.github/workflows/build-apk.yml`) writes one and runs `./gradlew assembleDebug` on JDK 17 + SDK 36; `v*` tag pushes attach the APK to a release. Debug builds stay **debug-signed**: when the `CI_DEBUG_KEYSTORE_BASE64` repo secret is set, `app/build.gradle.kts` decodes it into `build/ci-debug.keystore` and points `buildTypes.debug.signingConfig` at it (so every CI APK shares one stable signature — fresh runners would otherwise generate a new random debug key per run); `KEYSTORE_PASSWORD`/`KEY_ALIAS`/`KEY_PASSWORD` override the `android`/`androiddebugkey` defaults. Without the secret, CI uses the default per-run debug key.
- `gradle.properties` sets `parallel=true`, `Xmx=2048m`, UTF-8. `dependencyResolutionManagement` uses `FAIL_ON_PROJECT_REPOS` — never add `repositories {}` inside module build files.

## Architecture

Package root: `org.ravi.codeassist` (`app/src/main/kotlin/org/ravi/codeassist/`).

- `MainActivity.kt` — single launcher activity, hosts the UI shell. The SAF workspace picker stores both the resolved absolute path (`WORKSPACE_ROOT`) and tree URI (`WORKSPACE_SAF_URI`) and verifies the path is writable before accepting it.
- `ClipboardActivity.kt` — transparent, `singleInstance`/`noHistory`, `excludeFromRecents`; the invisible entry point triggered by the QS tile. Its `hasProcessed` one-shot guard is set in `onCreate` and deliberately never reset — focus loss/gain must not re-execute the same payload; don't "fix" it. It enforces a first-mutating-batch confirmation gate and runs transaction execution on `applicationContext` in a detached scope.
- `CodeAssistTileService.kt` — Quick Settings tile (`BIND_QUICK_SETTINGS_TILE`). Tapping it launches `ClipboardActivity`.
- `FloatingBubbleService.kt` — foreground service (`foregroundServiceType="dataSync"`), runs the overlay bubble.
- `AgentAccessibilityService.kt` — `BIND_ACCESSIBILITY_SERVICE`; config in `res/xml/accessibility_service_config.xml` (`flagRetrieveInteractiveWindows`, `flagReportViewIds`, `canPerformGestures`). This is the agent's eye/hand: capture overlay, control panel, bounding-box highlights, scroll-zone config, gesture dispatch, and element-signature matching. Long-running UI polls (`waitForMutationAndScrape`, plus the `autoResumeFromSentinel`/`resumeOrSync` resume paths) run on `serviceScope`, outside the agent's coroutine — they observe `AgentOrchestrator.isStopRequested()` so a Stop can interrupt them (see Stop token below).
- `AgenticViewModel.kt` — `AndroidViewModel` + StateFlows that drives `agent/AgentOrchestrator` (the agent loop).
- `CommandExecutor.kt` + `CommandExecutorUtils.kt` — envelope application and file validation. Shared helpers (`isPathSafe` path-traversal guard, `countOccurrences`, `ensureWorkspaceReady`) live in the `CommandExecutorUtils` object — reuse these instead of reinlining. Patch application and the non-mutating `previewPatch` share one strategy cascade (`resolvePatchText`: REPLACE_ALL → wildcard → exact → floating-indent → fuzzy → Levenshtein), so the pre-flight diff always matches what actually gets written. `validate()` runs `utils/CommandValidator.schemaError` first so malformed commands fail with precise schema errors before any filesystem checks.
- `EnvelopeParser.kt` — streaming state-machine parser (`ParseState`) that turns `:::CODE_ASSIST:::` payloads into `List<CodeCommand>`.
- `TransactionManager.kt` — staging across a command block; partial-success tolerant (NOT atomic by design — non-atomic saves tokens). Failed commands surface individually; successful ones still commit so the model re-emits only the failures. Before the first mutating batch of a session it lazily snapshots a one-shot git checkpoint (`AgentOrchestrator.sessionCheckpointRef` via `GitManager.createCheckpoint`) and tags it `codeassist-session-start`; every committed batch is additionally tagged `codeassist-round-<n>` so the "Undo Session" toolbox tool can reset to any round. `AgentPolicy` DENY rules are enforced here as pre-execution blocks (the single execution choke point shared by the loop and the QS-tile path). Feedback includes a per-file `--- FILE STATUS ---`, a `--- BATCH SUMMARY ---`, and a `--- STATE SNAPSHOT ---` (post-write line counts + top-level symbols via `WorkspaceScope.outlineFor`, plus git state via `GitManager.repositorySnapshot`, plus a `--- LAST COMMIT DIFF (HEAD) ---` stat of the just-committed batch via `GitManager.lastCommitDiffStat` so the model can verify exactly which lines landed).
- `GitManager.kt` — JGit staging + network ops. `initGit` creates repo + initial commit (+ `.gitignore`); `commitSelected(paths, message)` stages only chosen paths (auto-generates `generateCommitMessage()` when blank); `commitAllChanges` does full add; `tagCurrentHead`/`listCheckpoints` for round undo; `changesOverview()` drives commit preview + live status; `fileDiff`/`commitFileChanges` for per-commit sheets; extended ops `checkoutBranch`, `pullFromRemote`, `fetchRemote`, `createBranch`/`deleteBranch` (force=false), `mergeBranch` (`ensureMergeIdentity`), `discardWorkingChanges` (HARD reset, untracked preserved), `listRemoteDetails`/`addRemote`/`removeRemote`/`setRemoteUrl`; `cloneRepository`/`pushToRemote` (auto-unshallow via `depth=2147483647`); `commitsAheadWithFallback` falls back to `refs/remotes/<remote>/<branch>` then total HEAD count so Push shows `N to push` even without upstream (also sets upstream on first push like `git push -u`). All ops serialize via `Mutex` + clear `.git/index.lock`; `findEnclosingRepo` walks up for nested workspaces.
- `GitCredentialProfiles.kt` — persisted Git username/token profiles (JSON array in `CodeAssistPrefs` under `GIT_CRED_PROFILES`, active selection under `GIT_CRED_ACTIVE`). Managed from the Settings "Git Credentials" screen; the Clone/Push dialogs present an "Anonymous (no credentials)" + profile dropdown (`configureCredDropdown`/`resolveCredProfile` in `MainActivity`) instead of ad-hoc username/token fields.

- `agent/` — `AgentOrchestrator`, `AgentState`, `ToolboxManager`, `SessionTranscript`, `AgentPolicy`. `AgentOrchestrator` parks the loop after `MAX_LOOP_ITERATIONS = 25` rounds instead of halting: it sets `budgetExhausted` and `WAITING_FOR_USER`, and the "Resume Session" tool (via `resumeOrSync`) calls `resumeAfterBudgetExhaustion()` which resets the round counter and re-asserts the last injected prompt. Stuck-model guards: `recordRoundDigest` halts the loop after `MAX_IDENTICAL_ROUNDS = 3` consecutive identical observation digests (same failures re-emitted, no new output), and `awaitModelResponse` bounds each model wait (`MODEL_RESPONSE_TIMEOUT_MS`, re-asserts the last prompt exactly once on a missed response, then parks in `WAITING_FOR_USER`). A `PROTOCOL_DRIFT` guard recovers when the model "breaks character": a scraped non-envelope response that isn't a timeout/error (most often the model answering a plain human chat message as a chatbot) triggers `buildProtocolDriftPrompt`, which re-anchors rule 9 (a plain user message is a NEW GOAL, answered with exactly one envelope) and continues the loop — escalating after `consecutiveDriftRounds` (max 3) to a halt. The same drift recovery runs in the `resumeFromText` path (non-envelope, non-blank scrape) so a Resume tap can no longer re-park forever. Double-execution guard (three layers): `TransactionManager` records every successfully-applied mutating command's fingerprint (`AgentOrchestrator.recordExecutedCommand`), and both `startLoop` and `resumeFromText` split scraped payloads into envelopes (`splitEnvelopes`/`filterReexecuted`) so any envelope whose normalized mutating fingerprints were already executed in the recent window — or already queued in the SAME scrape (a write the model emitted twice in one message, or an envelope duplicated by stream stitching) — is dropped instead of re-applied; a fully-duplicate scrape parks with a "Duplicate envelope skipped" overlay. Independently, `CommandExecutor.guardedWrite` refuses an identical write to the same path already applied this session (session-scoped `CommandExecutorUtils` registry, cleared on session init/reset) — since `handleCreate` overwrites unconditionally and `handlePatch` can re-match a different occurrence, this last-line guard makes a second execution a no-op `[SKIPPED]` success instead of a second mutation. `resumeOrSync` additionally locks state to `WAITING_FOR_MUTATION` on entry so a sentinel auto-resume and a manual Resume tap cannot race the same scrape into the execution gate, and the confirmation overlay's "Allow for Session" button disables itself on tap so a double-tap can't fire `executeBatch` twice. A mechanical DONE gate blocks termination while `<ACTIVE_PLAN>` still has pending tasks — the model gets a `[PLAN_DONE: n]`/`[COMMAND: PLAN]` reconciliation prompt instead of a silent end. It owns a cooperative **Stop token**: `requestStop()` sets a `@Volatile` flag (and drops state to `IDLE`), `isStopRequested()` is polled by the accessibility service's off-loop polls, `clearStopRequest()` resets it (called on every session entry point and the Play/resume path). Short-term memory lives in `SessionTranscript` (structured plan checklist + rolling `RECENT_OBSERVATION_LOG` of the last ~5 transaction digests + action log; digests keep only failures/policy blocks/mutations plus the batch summary, and consecutive duplicates are collapsed; renders the `<ACTIVE_PLAN>`/`<RECENT_OBSERVATION_LOG>` blocks; compaction caps checklist items, digest size, and plan notes). Both reset on session init/reset. `ToolboxManager` is the single tool registry — the overlay drawer buttons and the floating-bubble menu both render from it via `getTool(id)` (no duplicated per-surface wiring). `AgentPolicy` holds persisted `deny <COMMAND>:<path-glob>` rules (JSON in prefs) enforced in `TransactionManager` and re-injected as `<POLICY>` in the boot prompt; no policy rule can weaken the DELETE/MOVE human-confirmation invariant.
- `utils/SystemPromptGenerator.kt` — builds the bootstrap system prompt (`generate`), pulled in by `AgentOrchestrator.buildSystemPrompt`. There is no real chat-app `system` channel; the whole prompt is typed as the first user message, so it drifts on long ReAct loops. Mitigations: an immutable `PRIMARY_RULES` block (rule 9: a plain user message is a NEW GOAL, still answered with exactly one envelope), `standingReminder` (re-anchors rules on every `TRANSACTION_RESULT`/`TRANSACTION_ERROR`), and `truncateForInjection` (caps oversized feedback and embedded `CodeAssist.md` content, e.g. 12000 chars for project context). The prompt is written opencode-style (`#`-sectioned) with a consequence-aware Guardrails section: every rule states what the app actually does on violation (e.g. mixed DONE is ignored, truncated envelopes are dropped, DELETE/MOVE can't be bypassed) so the model internalizes the protocol instead of treating it as decoration. Keep the tool list in sync with `EnvelopeParser`/`CodeCommand` (currently GLOB, OUTLINE, READ, GREP, PATCH, CREATE, DELETE, MOVE, PLAN, DONE).
- `database/` — Room (`CodeAssistDatabase`, `AgentRepository`, `AgentProfile`, plus `ElementRole`, `ElementSignature`, `ExecutionHistory` for accessibility capture). `onUpgrade` is non-destructive: idempotent, `try/catch`-wrapped `ALTER TABLE ADD COLUMN` migrations per version, never drop/recreate.
- `ui/` — `AgentOverlayManager`, `OverlayConfirmationManager`, `BoundingBoxView`, `ScrollZonePickerView`, `TransactionSummaryController`, `CommandOrbView`, `CommandRadialOverlay`. `AgentOverlayManager` hosts the drag orb (position clamped to the screen and persisted to `CodeAssistPrefs` `OVERLAY_POS_X`/`OVERLAY_POS_Y`) and a transient status chip (`updateStatus`, fades after ~2.8s; only used for explicit messages like "Stopped"). The orb is a custom-drawn `CommandOrbView`: dark ring track, glass core with a morphing play/stop icon, a breathing accent arc + pulsing aura while the agent works, a scale pulse on `WAITING_FOR_USER`/`ERROR`, and animated accent-color cross-fades. Tap the orb (not a drag, `ACTION_UP` within the orb bounds) = play/resume or stop; a 360ms hold opens `CommandRadialOverlay` — a separate `TYPE_ACCESSIBILITY_OVERLAY` window that springs a 6-tool radial ring around the orb (Resume/Init/Bounds/Reset/App/Exit), whose circle buttons dispatch through `ToolboxManager.getTool(id)`; Exit is a two-step inline confirm (tap again within 3s); tapping anywhere else (its own root `ACTION_DOWN`/`ACTION_OUTSIDE`, or the orb window's `ACTION_OUTSIDE`) dismisses it. The design is ported from `design/agent-overlay-prototype.html` (Concept B).
- `utils/` — fuzzy matcher, `CommandValidator` (per-command schema checks, first line of defense in `CommandExecutor.validate`), outline/signature extractors, tree minimizer, `WorkspaceScope` (bounded boot-time file tree + line-count index + post-write outline verification), `SystemPromptGenerator`, profile IO.

## Required permissions (granted by user, not tested headlessly)

- `MANAGE_EXTERNAL_STORAGE` ("All files access") — `requestLegacyExternalStorage="true"` also set. Note: `MainActivity.workspacePickerLauncher` resolves the SAF tree URI to an absolute `java.io.File` path via `Environment.getExternalStorageDirectory()` (deprecated on API 30+). JGit operates on that path with `java.io.File`, not SAF `DocumentFile`. On scoped-storage-only OEMs the resolved path may not match the SAF grant and git operations can silently fail — `verifyAndSaveWorkspace` catches this at pick time. Long-term fix is migrating to `DocumentFile`; do not assume SAF == File.
- `SYSTEM_ALERT_WINDOW` (bubble overlay), `QUERY_ALL_PACKAGES` (installed-app list), `POST_NOTIFICATIONS` (foreground service), accessibility service enabled in Settings.

## Code style / conventions

- Kotlin official style (`kotlin.code.style=official`).
- All sources live under `app/src/main/kotlin/...` (non-standard `kotlin` source set, not `java/`).
- Some dependencies are declared inline in `app/build.gradle.kts` rather than the catalog: `material` is duplicated (catalog + inline), while `lifecycle-viewmodel-ktx` and `kotlinx-coroutines-android` exist only inline — check both files before bumping.

## Protocol format (read before touching the parser)

Commands are clipboard payloads wrapped in `:::CODE_ASSIST:::` envelopes (closed by `:::END_CODE_ASSIST:::`) and parsed by `EnvelopeParser` as a state machine (`when(currentState)` over `ParseState`). The `CodeCommand` sealed class in `CodeCommand.kt` is `when`-matched across **five** files; adding a command type requires a branch in **all** of them or you'll silently fall through:
- `CodeCommand.kt` — add the `data class` with `isMutating`.
- `EnvelopeParser.kt` — add the `when (name)` branch and any `[FIELD:]` parsing.
- `CommandExecutor.kt` — both `when (command)` blocks (validation in `validate()`, dispatch in `execute()`).
- `TransactionManager.kt` — the `when` blocks for staging, commit message, and modified-path tracking.
- `ui/TransactionSummaryController.kt` — both `when (command)` blocks for the summary UI.

Only `:::CODE_ASSIST:::` envelopes are parsed. The `:::CODE_ASSIST_TRANSACTION_ERROR:::` / `:::CODE_ASSIST_TRANSACTION_RESULT:::` envelopes the app writes back to the LLM (in `TransactionManager` and `AgentOrchestrator`) are output-only — no parser branch exists for them.

PATCH bodies use symmetric bracket markers `[SEARCH]` / `[END_SEARCH]` / `[REPLACE]` / `[END_REPLACE]` (`EnvelopeParser` states `IN_SEARCH`/`IN_REPLACE`) — never the git-conflict style `<<<<<<< SEARCH`/`=======`/`>>>>>>> REPLACE`, since a bare `=======` line reads as a markdown Setext heading and can be dropped by chat-app rendering when the ```text fence is lost. The parser accepts a bare `[REPLACE]` as a search-block closer too (recovery when the model skips `[END_SEARCH]`), and the extracted SEARCH is always verified against the file before writing, so a mis-split degrades to a rejection, never silent corruption. `EnvelopeParser` normalizes chat-app artifacts (smart quotes, NBSP, zero-width chars) on the dispatch line via `CommandExecutorUtils.normalizeForMatch`; body lines stay raw. `CommandExecutor.resolvePatchText` cascades REPLACE_ALL → wildcard → exact → `NORMALIZED_EXACT` (unique match of quote/space-normalized SEARCH, applied to actual file bytes via `findNormalizedRange`) → floating-indent → fuzzy → Levenshtein.

`AutoAllowMode` (in `CodeCommand.kt`) gates auto-approval in `ClipboardActivity` and `agent/AgentOrchestrator.kt`. `READ_WRITE` and session auto-allow only auto-approve *non-destructive* mutations (PATCH/CREATE); every `isDestructive` command (DELETE/MOVE) requires human confirmation regardless of mode — it overrides even an armed "Allow for Session". `Done` halts the loop (`HALT_DONE`) and is filtered out before staging in `TransactionManager`. There is no `AskUser` command — it was removed app-wide; the loop instead auto-approves and proceeds (see `default_to_action` in the prompt).

`[COMMAND: PLAN]` is a non-mutating task-tracker command: a non-empty `[CONTENT]` checklist replaces the stored plan in `AgentOrchestrator` (`applyPlan`), while `[PLAN_DONE: n]` and `[PLAN_NOTE: ...]` work standalone. It is filtered out of the file pipeline everywhere and the live checklist is re-injected every round as `<ACTIVE_PLAN>`.

The boot prompt embeds a `WORKSPACE TREE` + `FILE INDEX` from `WorkspaceScope`; every batch result/error carries a `--- STATE SNAPSHOT ---` with post-write verification and git state, plus `<ACTIVE_PLAN>` and `<RECENT_OBSERVATION_LOG>`. These blocks are output-only like the error/result envelopes.

## What NOT to change without thinking

- `applicationId` and `namespace` (`org.ravi.codeassist`) — changing them breaks the accessibility-service binding and SAF grants.
- The `dataSync` foreground service type on `FloatingBubbleService` — required for the long-running bubble session; another type is rejected on Android 14+.
- `launchMode="singleInstance"` and `noHistory="true"` on `ClipboardActivity` — these prevent it leaking into recents.
- `ClipboardActivity.hasProcessed` — resetting it on focus/`onResume` would re-execute the same clipboard payload.
- `dependencyResolutionManagement` uses `FAIL_ON_PROJECT_REPOS` — do not add `repositories {}` inside module build files.
